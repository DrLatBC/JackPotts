# Joker values come from structured state, not description text

The bot used to parse each joker's on-screen description for its numbers ("Currently X1.6 Mult"). That text only exists where the game's UI code runs, so it tied every gamestate source to the live client's description builder: a simulator would have to reproduce it word for word. The gamestate now sends raw game counters (card ability fields, per-frame tallies, a `counters` block), and the bot computes each joker's current value from them in one place (`joker_effects/live_values.py`, each formula citing its line in the game's `card.lua`). The fork and the Jackdaw adapter send the same fields, so live play and simulation go through one path. Description text is kept for logs only. A new joker whose value the game computes when it draws the description needs a formula there and, if it reads a new game value, a field in both the fork and the adapter.
