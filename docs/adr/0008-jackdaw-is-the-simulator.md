# Jackdaw is the simulator; the game's own Lua is the cross-check

[0007](0007-headless-simulator-for-game-volume.md) planned to run Balatro's own Lua headless first. The spike got it running: the modded game boots in the game's `lua51.dll`, and the bot plays it through the fork's endpoints (`sim/host.py`). But every action still walks the animation and UI code, at about 0.2 s of simulation time per action, roughly a thousand times too slow for training-scale volume. [Jackdaw](https://github.com/TylerFlar/jackdaw-balatro), an existing Rust reimplementation of the same game version and Steamodded build, serves balatrobot's API at thousands of requests a second. Replayed request for request against the headless Lua over a full bot game, it agreed on every rules field except the differences in its own deviation catalog. So Jackdaw is the engine for volume. A thin adapter (`sim/jackdaw_adapter/`) adds the fields our fork sends, and the headless Lua stays as the exact oracle for checking both. Jackdaw assumes a fully unlocked profile, so a sim game and a live game on a partly locked profile see different shop and pack pools.
