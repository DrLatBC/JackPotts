# Simulator games are kept as replays

The simulator plays thousands of games an hour per instance, and each game's full record (decision snapshots, play-by-play, shop events, log text) is about 360 KB to upload and about 90 KB in the dashboard's database, which neither the upload limit nor the database can absorb at that rate. The simulator is deterministic, so a game's seed and the requests that changed it reproduce every state the game passed through; the bot therefore saves each simulator game as a replay of about 650 bytes in `bot_log/<port>/replay_<session>.jsonl.gz` (`balatro_bot.replays`) and sends the dashboard only the game's summary: result, rounds, ante snapshots, jokers, consumables, blind choices. Anything else about a game is rebuilt by replaying it on the same simulator version, in whatever form is needed, which also suits the purpose the games now serve: a benchmark and a starting point for a model that learns by playing the simulator itself, not a store of fixed training rows. The cost is that the dashboard's per-game detail views (play-by-play, shop and pack decisions, hand scores, log) are empty for simulator batches. Live Balatro games cannot be replayed and keep their full records. `scripts/replay_check.py` replays a file and checks each game ends where the bot's did.
