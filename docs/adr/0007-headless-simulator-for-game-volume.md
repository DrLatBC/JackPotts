# A headless Balatro for training-scale game volume

The ML goal is learning from millions of games, and the real client can't reach that. Six instances on one desktop play about 280 games an hour, and about 95% of a game's frames go to animations the bot waits through. So training data will come from a headless simulator that runs Balatro's rules without the frame loop. We build it from the game's decompiled source rather than from observed behaviour, and check it against the live game: the same seed is played in both, and the full state is compared after every action, so any drift points at one mechanic. The approaches are tried in order of cost. First, run the game's own Lua in a bare LuaJIT, with LÖVE stubbed out and the event queue stepped to completion, reusing the fork's endpoints so the bot drives it unchanged. Second, only where that proves too entangled with the UI, port the rules to Python. A faster real client, using bigger frame steps in the fork, is the fallback and the baseline. This moves the project past [0001](0001-rule-engine-not-ml.md): the rule engine stays the policy for now, but improvement increasingly comes from data at scale.

The approach was settled by the spike: see [0008](0008-jackdaw-is-the-simulator.md).
